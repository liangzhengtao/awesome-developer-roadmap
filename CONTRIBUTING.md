# Contributing to Awesome Developer Roadmap

Thank you for your interest in contributing! This project aims to help developers navigate their career paths, and every contribution makes it better.

## How to Contribute

### 1. Reporting Issues

- Use the [Issue Tracker](https://github.com/liangzhengtao/awesome-developer-roadmap/issues) to report bugs or suggest improvements
- Search existing issues before creating a new one
- Use the provided issue templates when available

### 2. Suggesting Changes

For small changes (typos, formatting fixes):
1. Fork the repository
2. Create a branch: `git checkout -b fix/your-fix`
3. Make your changes
4. Submit a pull request

For larger changes (new roadmaps, major restructuring):
1. Open an issue first to discuss the change
2. Wait for approval before starting work
3. Follow the same fork/branch/PR process

### 3. Adding New Roadmaps

If you'd like to add a new roadmap:
1. Open an issue proposing the new roadmap
2. Include the roadmap title, target audience, and rough outline
3. Wait for feedback and approval
4. Follow the existing roadmap format (see below)

### 4. Updating Salary Data

Salary data should be:
- Sourced from reliable data (Glassdoor, Levels.fyi, LinkedIn Salary)
- Updated at least annually
- Include source references when possible
- Cover major markets (US, EU, Asia)

## Roadmap Format

Each roadmap should include:
- ASCII art diagram showing career progression
- Skills checklist with checkboxes
- Learning resources for each stage
- Project ideas for portfolio building
- Interview preparation tips
- Salary expectations by level
- Chinese translation (中文版本)

## Style Guidelines

### Markdown
- Use ATX-style headers (`#`, `##`, `###`)
- Use `-` for unordered lists
- Use `1.` for ordered lists
- Use backticks for inline code
- Use fenced code blocks for multi-line code
- Keep lines under 120 characters when possible

### Content
- Be concise and actionable
- Use clear, professional language
- Include both free and paid resources
- Provide specific links when possible
- Keep information current and accurate

### Checkboxes
Use `- [ ]` for unchecked items:
```markdown
- [ ] Skill to learn
- [ ] Another skill
```

## Code of Conduct

Please read our [Code of Conduct](CODE_OF_CONDUCT.md) before contributing.

## Pull Request Process

1. Update the README.md if you're adding a new roadmap
2. Update the CHANGELOG.md with your changes
3. Ensure all links are working
4. Request review from maintainers

## Recognition

Contributors will be:
- Listed in the README.md (if desired)
- Mentioned in release notes
- Given credit in the CHANGELOG.md

## Questions?

If you have questions about contributing:
- Open an issue with the "question" label
- Join our community discussions
- Reach out to the maintainers

Thank you for helping developers navigate their careers! 🚀
