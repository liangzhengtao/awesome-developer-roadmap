## The Two Paths: Tech Lead vs Engineering Manager

| Aspect | Tech Lead (TL) | Engineering Manager (EM) |
|--------|----------------|--------------------------|
| Focus | Technical excellence | People and delivery |
| Coding | 30-60% of time | 0-20% of time |
| Reports | Usually no direct reports | 5-12 direct reports |
| Decisions | Architecture, tech stack | Hiring, team structure |
| Growth | Principal/Staff Engineer | Director/VP Engineering |

Many companies combine these roles, especially at smaller organizations.

## Key Frameworks & Tools

### 1:1 Meeting Framework
```
Weekly 1:1 Structure (30-60 min):
1. Check-in (5 min) - How are you doing?
2. Priorities (10 min) - What are you working on?
3. Blockers (10 min) - What's blocking you?
4. Growth (10 min) - How can I help you grow?
5. Feedback (5 min) - Any feedback for me?
```

### OKR Framework
```
Objective: Improve system reliability
├── Key Result 1: Reduce P1 incidents from 5/month to 2/month
├── Key Result 2: Achieve 99.95% uptime SLA
└── Key Result 3: Reduce mean time to recovery from 2h to 30min
```

### Performance Review Template
```
1. Accomplishments (what was delivered)
2. Impact (business impact)
3. Growth (skills developed)
4. Areas for improvement
5. Goals for next period
```

### RACI Matrix
```
| Activity          | Tech Lead | EM  | PM  | Stakeholder |
|-------------------|-----------|-----|-----|-------------|
| Architecture      | R/A       | C   | I   | I           |
| Sprint Planning   | C         | A   | R   | I           |
| Hiring            | C         | R/A | I   | I           |
| Tech Debt         | R/A       | C   | I   | I           |
| Feature Delivery  | C         | A   | R   | I           |

R=Responsible, A=Accountable, C=Consulted, I=Informed
```

## Interview Preparation

### Common Interview Topics

1. **Technical Leadership**
   - Describe a technical decision you led
   - How do you handle disagreements?
   - How do you balance tech debt and features?
   - How do you stay technically relevant?

2. **People Management**
   - How do you handle underperformers?
   - Describe your 1:1 approach
   - How do you develop team members?
   - How do you handle conflict?

3. **Delivery & Process**
   - How do you estimate projects?
   - How do you handle scope creep?
   - Describe your sprint process
   - How do you manage dependencies?

4. **Strategy & Vision**
   - How do you create a technical roadmap?
   - How do you align with business goals?
   - How do you handle technical debt?
   - How do you evaluate new technologies?

5. **Scenario Questions**
   - A key engineer wants to leave - what do you do?
   - Your team is behind on a deadline - how do you handle it?
   - There's a production incident - walk me through your response
   - You need to cut 20% of the roadmap - how do you decide?

## 中文版本 - 技术负责人 / 工程经理路线图

### 概述

这是一份从高级工程师到技术副总裁的完整成长路线图。

### 两条职业路径

| 方面 | 技术负责人 (TL) | 工程经理 (EM) |
|------|-----------------|---------------|
| 重点 | 技术卓越 | 人员与交付 |
| 编码时间 | 30-60% | 0-20% |
| 下属 | 通常无直接下属 | 5-12 名直接下属 |
| 决策 | 架构、技术栈 | 招聘、团队结构 |
| 晋升方向 | 首席/杰出工程师 | 总监/VP 工程 |

### 阶段一：从高级工程师转型（0-12个月）

**必学技能：**
- [ ] 领导力基础（影响力、情商、冲突解决）
- [ ] 沟通技能（技术文档、演讲、利益相关者沟通）
- [ ] 项目管理（敏捷/Scrum、估算、风险管理）
- [ ] 团队动态（心理安全、远程协作）

**推荐学习资源：**
- 《成为技术领导者》
- 《高效能人士的七个习惯》
- 《关键对话》
- Rands Leadership Slack 社区

### 阶段二：技术负责人技能（12-24个月）

**技术领导：**
- [ ] 架构设计领导力
- [ ] 代码质量把控（Code Review、标准制定）
- [ ] 技术战略（技术路线图、创新时间）

**团队领导：**
- [ ] 导师制（职业发展、技能差距分析）
- [ ] 决策制定（数据驱动、权衡分析）
- [ ] 交付管理（Sprint 规划、风险缓解）

### 阶段三：工程管理（18-30个月）

- [ ] 人员管理（1:1 会议、绩效评估、职业发展）
- [ ] 招聘（JD 编写、面试流程、候选人评估）
- [ ] 团队建设（团队组成、文化建设、远程管理）
- [ ] 绩效管理（OKR 目标设定、反馈、认可）

**推荐学习资源：**
- 《高产出管理》（安迪·格鲁夫）
- 《管理之路》
- 《彻底坦率》

### 阶段四：高级工程经理（24-36个月）

- [ ] 组织设计（团队拓扑、Conway 定律）
- [ ] 战略规划（工程战略、资源分配）
- [ ] 跨团队领导（依赖管理、架构对齐）
- [ ] 预算管理（预算规划、成本优化）
- [ ] 高管沟通（董事会汇报、战略对齐）

### 阶段五：总监 / VP 工程（36个月以上）

- [ ] 工程战略（多年技术愿景、技术押注）
- [ ] 业务对齐（产品-工程协同、收入影响）
- [ ] 组织领导力（文化建设、变革管理、继任规划）
- [ ] 人才战略（雇主品牌、留存策略、多元化）
- [ ] 创新（研发策略、创新实验室、开源战略）

### 关键框架

**1:1 会议结构（30-60分钟）：**
1. 状态检查（5分钟）- 最近怎么样？
2. 工作重点（10分钟）- 在做什么？
3. 阻碍因素（10分钟）- 有什么阻碍？
4. 成长（10分钟）- 如何帮助成长？
5. 反馈（5分钟）- 对我有什么反馈？

**OKR 框架示例：**
```
目标：提升系统可靠性
├── 关键结果 1：P1 事件从每月 5 次降至 2 次
├── 关键结果 2：SLA 可用性达到 99.95%
└── 关键结果 3：平均恢复时间从 2 小时降至 30 分钟
```
